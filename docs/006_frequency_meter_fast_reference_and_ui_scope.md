# 006 频率计快速参考通道与界面参数边界

## 1. 本次结论

- 原 `0x0070--0x0072` 触发式精密测量状态机和 `0x0110--0x0113`
  结果寄存器不变，仍是上位机正式测量通道。
- 新增并行快速参考累加器，默认每 `62,500,000` 个 `125 MHz` 时钟
  发布一次，即 `0.5 s` 更新一次。
- 快速结果只用于 LCD 和上位机参考显示，不能替代原触发式精密测量结果。
- LCD 主页面沿用现有频率行，不增加范围提示；中心频率编辑范围为
  `4--250 kHz`，其中 `5--200 kHz` 为标准设计范围，`200--250 kHz` 为扩展范围。详细页面布局以 `007_lcd_ui_and_controller_architecture.md`
  为准。
- MCU 通信协议已按 96 字节平面寄存器重构，STM32F030 已在第一页第八行显示
  ARM 换算后的快速频率计结果。最终寄存器表见
  `009_three_controller_control_protocol.md`。

快速通道仍累加现有 `Freq_Meter_Phase_Add`，没有修改 DDC、PLL、PID 或原始
触发计数器。它提供独立的窗口计时、80 bit 累加、结果快照、窗口快照和更新
序号。

## 2. FPGA 寄存器

| 索引 | 方向 | 含义 |
|---|---|---|
| `0x0073` | R/W | 快速更新窗口，单位为 `clk1` 周期；默认 `62,500,000` |
| `0x0114` | R | bit 0 为 valid，bits 31:1 为 31 bit 更新序号 |
| `0x0115` | R | 快速累加结果 bits 31:0 |
| `0x0116` | R | 快速累加结果 bits 63:32 |
| `0x0117` | R | 快速累加结果 bits 79:64 |
| `0x0118` | R | 产生该结果时实际采用的窗口周期数 |

窗口配置只在窗口边界生效。这样一次快照始终对应单一、明确的窗口长度。
RTL 对寄存器值 0 做一周期防御性处理；ARM 的 PC 写命令直接拒绝 0。

设 80 bit 累加结果为 `A`，结果窗口为 `N`，则参考频率为：

```text
frequency_hz = A * 125000000 / (N * 2^33)
```

这里必须使用 `2^33`：快速通道累加的 `Freq_Meter_Phase_Add` 来自
`Reference_frequency_DDC_Phase[46:15]`，相对于标准 32 bit DDS 频率字多保留
一位。ARM 使用结果快照随附的实际窗口 `N` 计算，而不是假定当前配置窗口，
因此窗口刚切换时也不会按错误间隔换算。

软件应先读 `0x0114`，再读结果和窗口，最后重读 `0x0114`；两次状态不同就
重读。ARM 的新读命令已经执行这一一致性检查。

控制寄存器中的快速更新间隔范围为 `10--34359 ms`。上限来自
`floor((2^32-1) / 125000)`，保证毫秒值转换成 `125 MHz` 周期数时不溢出
32 bit FPGA 窗口寄存器。

## 3. ARM/PC 新命令

| 命令 | 方向 | 载荷/返回 |
|---|---|---|
| `0x1C` | PC 读 | status 4 B、80 bit result 10 B、result window 4 B、configured window 4 B |
| `0x98` | PC 写 | `uint16 interval_ms`，小端，范围 `10--34359`，事务式临时提交 |

当前外部 PC 项目还没有实现这两个新命令。新 PC 驱动应先识别协议版本 3：日常
快速显示优先读取 `0x1D` 控制区中的整数 Hz，`0x1C` 只用于原始数据诊断，`0x98`
只修改物理毫秒参数且不写 EEPROM。旧设备继续使用原来的
`0x15/0x16/0x17/0x94/0x95` 触发测量流程。

## 4. 老上位机的实际角色

这里必须区分“协议驱动存在写接口”和“实际负责配置管理”。旧系统中，锁相环
参数的实际管理端是 LCD 单片机，不是上位机。

### 4.1 当前主界面可操作

1. PLL 开/关。
2. 频率计门时间，界面单位为秒，PC 换算为 `125 MHz` 时钟数。
3. 频率计手动触发。
4. 频率计复位。

主界面的“实时频率”和“重频”是显示项，不是设置项。采集卡平均次数、采样
周期等属于采集系统参数，不属于锁相环或频率计参数。

### 4.2 驱动层存在、旧协议可以发送，但不负责日常管理

- PLL：中心频率、MUL、DIV、相位/频率残差阈值、正负修正限幅、四个旧环路
  数值、DAC 幅度、开/关。
- 频率计：中心频率、相位/频率阈值、正负限幅、旧 P/I/II/D、门时间、触发、
  复位。

这些 API 没有接到当前主界面的参数编辑控件，属于遗留协议能力或调试入口，
不能据此把参数归为“上位机管理”。正常工作时，上位机读取状态、控制测量，
LCD/按键模组负责锁相环参数设置。

另外，旧 PC 的 `0x86` 载荷命名仍是 `P/I/II/D`，当前 ARM 已将四个位置解释
为 `Kp_track/Ki_track/Kf_acquire/Kf_blend`，两者语义不兼容。

### 4.3 代码遗留但当前 ARM 已停用

- 微波源频率/功率与开/关命令。
- EEPROM 加载/保存命令。
- VBIAS DAC/ADC 命令。

这些命令在老 PC 驱动中仍有函数，但当前 ARM 分发处理已注释，不能算当前
可用功能。

## 5. 当前 LCD 管理的参数

按当前 STM32F030 项目内代码，主页面可设置：

1. 微波源开/关、功率、频率。
2. PLL 开/关。
3. PLL 中心频率。
4. MUL、DIV。
5. DAC 输出幅度。
6. 频率残差阈值、相位残差阈值。

副页面可设置：

1. 旧 PLL P、I、II、D。
2. 正修正上限、负修正下限。

这不是单纯的显示界面。STM32F030 修改上述参数后，会把从中心频率到 DAC
幅度在内的 34 字节 PLL 配置写入 STM8；STM8 通过 UART `0xC4` 命令转发给
ARM；ARM 完整校验候选配置后，直接写入 FPGA 中发生变化的活动寄存器。因此旧系统的参数所有权和日常管理入口
明确位于 LCD/按键模组。

当前存在一个迁移错位：LCD 的四个字段仍显示为 `P/I/II/D`，但 ARM 已按顺序
把它们写入 `Kp_track/Ki_track/Kf_acquire/Kf_blend`。通信链路有效，但字段名称
与算法含义不一致，重构时必须改名并重新确定调节范围。

微波源三个设置在两个页面的控制表中复用。LCD 目前没有频率计测量字段；主
页面最下方现有“输出”频率是用中心频率和 `PLL_PID_OUT` 推算，不是独立频率
计结果。重构时应保留这一行的位置并改用快速参考结果，尽量不改变布局。

## 6. 新系统参数重要程度

### A 级：LCD 日常设置与持久化管理

- DPLL 中心频率，LCD 可设置范围为 `4--250 kHz`。
- DPLL 开/关。
- MUL、DIV。
- DAC 幅度。
- 正负修正限幅。
- 相位/频率锁定阈值。
- 四个主要环路调节量，界面名称为追踪P、追踪I、捕获f、过渡f，不再显示
  含义错误的 `P/I/II/D`。
- 微波源开/关、频率、功率。
- 快速参考频率只显示，不在 LCD 上设置更新窗口。

### B 级：上位机测量与监视

- 快速参考更新窗口。
- 原触发式精密频率计门时间、触发和结果读取。
- 锁定状态、环路状态、失锁原因、相位/频率误差监视。
- 可保留协议级参数读写接口用于调试和维修，但不作为日常配置所有者，也不应
  自动覆盖 LCD/EEPROM 保存的配置。

### C 级：上位机高级调试

- 幅度进入/退出阈值。
- acquire/blend/loss dwell。
- holdover/measurement timeout。
- `Kf_acquire/Kf_blend/Kf_track`。
- `Kp/Ki blend/track`。
- phase setpoint、manual offset。
- debug DAC source/format/gain/offset。

### D 级：ARM profile 内部生成

- CIC R/shift、FLL delay、warmup、IIR 模式与系数。

这类参数与频点 profile 强耦合，不应让 LCD 单独修改。上位机可在专家页查看，
但普通操作应由 ARM 根据中心频率选择成套 profile。

## 7. 高级 DPLL 参数解释

### 7.1 正负修正限幅

它限制环路能在中心频率两侧施加的最大 NCO 修正量。正限幅控制最高能向上追
多少，负限幅控制最低能向下追多少。范围太小会在输入偏差较大时顶住限幅而
无法捕获；范围太大会允许错误信号或瞬态把输出拉得过远。两侧可不对称，但
必须满足正值大于等于 0、负值小于等于 0。

### 7.2 phase/frequency lock threshold

phase threshold 是允许的相位误差窗口，frequency threshold 是允许的瞬时频率
误差窗口。状态机只有在误差进入相应窗口并持续满足 dwell 条件后才进入更稳定
的状态。阈值太紧会在噪声下频繁失锁，太松会把明显偏差也报告为锁定。它们是
判定门限，不是环路带宽，也不是修正限幅。

### 7.3 magnitude enter/exit

这是输入信号存在判定的迟滞门限。幅度上升超过 enter 才承认信号有效；幅度
下降低于 exit 才承认信号丢失，通常 enter 必须高于 exit。两条门限避免噪声在
单一阈值附近反复切换“有信号/无信号”。设置过高会漏掉弱信号，过低会把噪声
当成有效输入。

### 7.4 acquire/blend/loss dwell

dwell 表示状态转换前必须连续满足条件的有效测量次数。acquire dwell 防止一次
偶然的好样本就宣布捕获；blend dwell 决定从粗捕获过渡到混合控制需要稳定多
久；loss dwell 决定连续多少次坏样本才确认失锁。值小则反应快但容易抖动，值
大则稳定但捕获和失锁报告更慢。

### 7.5 holdover timeout 与 measurement timeout

measurement timeout 限制两次有效 detector 测量之间允许的最大间隔，超时说明
测量链停顿或没有形成有效样本。holdover timeout 是信号暂时丢失后允许保持上
一次控制结果的时长；超过后必须退出保持并重捕获。前者监视“测量是否继续到
来”，后者决定“丢测量后还能维持多久”，不是同一个概念。

### 7.6 Kf_acquire/Kf_blend/Kf_track

三者是频率环 FLL 在不同状态下的增益。`Kf_acquire` 用于大频差粗捕获，通常最
积极；`Kf_blend` 用于 FLL 与相位环共同工作的过渡状态；`Kf_track` 用于锁定后
慢速消除频率漂移。过大会捕获快但噪声和振荡增大，过小则响应迟钝甚至无法在
限定时间内拉入。

### 7.7 Kp/Ki blend/track

`Kp` 是相位误差的即时比例修正，主要影响响应速度和阻尼；`Ki` 累积长期相位
误差，用于消除稳态偏差。blend 组用于过渡状态，track 组用于稳定跟踪。Kp 太
大会抖动或振荡，太小会响应慢；Ki 太大会积分摆动和顶限幅，太小会留下长期
偏差。四个值必须作为 profile 一起验证，不能只凭单个数值判断好坏。

### 7.8 phase setpoint 与 manual offset

phase setpoint 是相位环希望维持的目标相位误差；当前正弦输入链采用约
`-pi/2`，这是检测器/IQ 定义的一部分，不代表物理上“相位应为零”。manual
offset 是在闭环修正之外人工叠加的固定频率偏移，适合校准或测试。误设
setpoint 会产生持续的相位控制偏差，误设 manual offset 会让整个锁定频率整体
偏移，因此都不适合放到 LCD 日常页面。

### 7.9 debug DAC source/format/gain/offset

source 选择输出到调试 DAC 的内部信号；format 决定该信号按有符号、无符号或
特定截位方式显示；gain 调整显示幅度；offset 调整显示直流中心。这四项只改变
DAC1 调试观察，不应改变 DPLL active profile、锁定状态或正式 DAC0 输出。错误
设置会造成示波器上波形饱和、反相或偏置，但不应被当作环路参数保存到 LCD
常用配置。

### 7.10 精密频率计D项与D滤波

精密频率计的`gain_d`保留在PC完整API中，和P/I/I2一样，更新后清理该频率计
PID的内部状态。D滤波系数不再作为公开API字段，由ARM启动时固定写入，当前为
`0x0000FFFF`。这样后续调整D滤波只需要更新ARM固件，不需要修改或重新布线HDL。
